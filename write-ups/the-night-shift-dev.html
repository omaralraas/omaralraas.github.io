CTF Write-up: The Night-Shift Dev

Challenge Overview

Objective: Discover an exposed source code repository on the Byte Lotus guest-experience web platform and recover the hidden flag.

"He booked the quiet room. It's not on the floor plan, not in the brochure, not on any door. But port 8080 is wide open, and the rooms it never lists are the ones worth finding."

The challenge tells us that the Byte Lotus guest-experience platform was deployed in a hurry and the night-shift developer "shipped more than the website." The itinerary is clear: dump exposed source code and find the flag. The mention of hidden rooms and unlisted paths immediately points toward web directory enumeration.

Methodology

STEP 1 Manual Reconnaissance

Before reaching for any automated tools, I started by visiting the target website at http://MACHINE_IP:8080 in my browser. I conducted initial manual reconnaissance:

  • Inspected the page source code for any hidden comments, hardcoded paths, or developer notes.
  • Checked for common directories manually by navigating to paths like /admin, /Rooms, and /login.
  • Reviewed the HTML, CSS, and JavaScript files loaded by the page for any references to internal endpoints.
✗ No hidden paths, comments, or clues were found through manual inspection.

Manual browsing yielded nothing useful. It was time to bring in automated enumeration tools.

STEP 2 Directory Enumeration with Gobuster

The challenge briefing explicitly mentioned that "the rooms it never lists are the ones worth finding" — a direct hint toward directory enumeration. This technique uses a wordlist to brute-force common directory and file names against a web server, looking for paths that aren't linked anywhere on the site but still respond.

I used Gobuster with the common.txt wordlist as a starting point:

gobuster dir -u http://MACHINE_IP:8080 -w /usr/share/wordlists/dirb/common.txt

Gobuster quickly completed its scan and returned a single, critical result:

✓ FOUND — .git/HEAD (Status: 200) [Size: 21]

A Status 200 response on .git/HEAD confirmed that the web server was exposing its entire .git directory to the public. This is a well-known and dangerous misconfiguration — it means the developer deployed the application directly from a Git repository and forgot to exclude the .git folder, effectively leaking the entire source code history of the project.

STEP 3 Dumping the Exposed Git Repository

A .git directory cannot simply be browsed through a web browser — its contents are binary objects, refs, and packfiles. To reconstruct the full repository from the exposed files, I used a specialized tool called git-dumper.

I installed git-dumper on my Kali machine using pipx:

pipx install git-dumper

Then I ran it against the target to download the entire repository:

git-dumper http://MACHINE_IP:8080/.git/ website-source

git-dumper systematically fetched all Git objects, references, and packfiles from the exposed .git directory and rebuilt a fully functional local copy of the repository in the website-source folder.

STEP 4 Extracting the Flag

With the repository successfully cloned to my local machine, I navigated into the website-source directory and began examining the files. The flag was sitting in plain sight inside the project's README.md file — left behind by the night-shift developer who clearly shipped more than just the website.

cd website-source
cat README.md
✓ FLAG CAPTURED — Found directly in README.md

Flag

🚩 Flag found in README.md

Key Takeaways

This challenge demonstrates a real-world vulnerability that is alarmingly common in production environments:

📂 Exposed .git Directories

Deploying a project by copying the entire working directory (including .git) to a web server is one of the most common deployment mistakes. It exposes the full source code, commit history, credentials, and internal notes to anyone who knows to look for it.

🔍 Directory Enumeration is Essential

The .git folder was never linked from the website itself. Without running a directory enumeration tool like Gobuster, there would have been no indication it existed. This reinforces why automated enumeration is a fundamental step in any web application assessment.

📝 Wordlist Selection Matters

The common.txt wordlist was sufficient to find the .git/HEAD endpoint in this case. However, more obscure paths may require larger wordlists such as directory-list-2.3-medium.txt. Choosing the right wordlist — or escalating to progressively larger ones — is a key part of effective enumeration.

🛡️ Defensive Recommendation

Web servers should be configured to explicitly deny access to .git directories. In Nginx, this can be done with location ~ /\.git { deny all; }. In Apache, use RedirectMatch 404 /\.git. Additionally, deployment pipelines should never copy .git folders to production — use git archive or a proper CI/CD build step instead.
